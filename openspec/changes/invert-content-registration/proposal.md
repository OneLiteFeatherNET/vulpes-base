# Proposal

**Conventional Commits:** `feat(registry)!: let generated content register itself`

## Why

Today `vulpes-base` is a template rather than a library. Its handwritten code pulls the generated classes in directly: `CustomItemImpl` builds its registry from `CustomItemEntries.entries()`, and the public interfaces extend generated sealed types such as `CustomItems`. Placeholders for those classes are committed under `src/autogenerated/java`, and the generator overwrites them in a clone of this repository. That only works if handwritten and generated code are compiled together.

Content releases are moving to data JARs, and code generation moves into the Gradle plugin `net.onelitefeather.vulpes`, which runs in the game's build (design document "2026-10-28 — Vulpes: Content-Releases ohne Git (Design)", section "Templates"). For that, the direction has to flip: `vulpes-base` becomes a normal dependency from Reposilite, and the generated code builds its entries with public factories of this library and hands them over at server start.

## What Changes

- **BREAKING** Remove `src/autogenerated/java` and every reference to generated types (`*Entries`, `*Keys`, the sealed `CustomItems`, `CustomAttributes`, `CustomSounds`, `CustomFontSymbols`, `CustomAdvancements`). The public interfaces no longer extend generated types.
- New `VulpesContent` interface that a content project implements (generated as `<Project>Content`): it lists its items, attributes, sounds, font symbols and advancements, and the deprecated alias keys of renamed entries.
- New `Vulpes.bootstrap(VulpesContent...)` that validates the content (unique keys across all projects, advancement parents present and acyclic, aliases pointing to existing keys) and returns an immutable `VulpesRegistries` with one `Registry` per type. Lookups by an alias key resolve to the current entry.
- **BREAKING** Remove the static accessors `fromKey`, `values`, `registry`, `roots` and `children` on the content interfaces. Registries are reached through the `VulpesRegistries` instance; typed access uses the generated constants. `AdvancementTabs.createAll` takes the advancements to build from.
- Public factories replace the package-private constructors: `CustomItem.of(Key, ItemStack)`, `CustomAttribute.of(...)`, `CustomSound.of(Key, Float)`, `CustomFontSymbol.of(Key, Key, FontSymbol)`, `CustomAdvancement.builder(Key)`. `ItemComponentDecoder` becomes the public `ItemComponents.apply(ItemStack.Builder, String...)`.
- **BREAKING** `CustomAttribute` gains `minimumValue`, `translationKey` and `synced`, matching the content contract (format 1).

## Non-goals

- No code generation in this repository; that lives in the Gradle plugin.
- No runtime reloading of content (`vulpes-runtime`).
- No resource pack handling; pack constants are generated by the plugin.
- No `ServiceLoader` discovery; registration is explicit.
- The artifact coordinates change separately in `publish-as-vulpes-base`.

## Impact

- **Games**: replace static lookups with the `VulpesRegistries` returned by `Vulpes.bootstrap(…)`, and add the plugin. Every current consumer depends on the generated clone anyway and has to migrate with the content release switch.
- **vulpes-gradle-plugin**: its `minestom` template generates against this API (change `port-content-codegen` there).
- **Tests**: tests that rely on empty placeholder entries are replaced by tests that bootstrap their own content.
